# ADR-0002. similarityThreshold 를 0.2 로 낮추고 관련성 판단을 LLM 에 위임

- 상태: 채택
- 날짜: 2026-09-30

## 배경

`VectorStoreDocumentRetriever` 에 `similarityThreshold(0.5)` 를 두고 시작했다.
흔히 쓰이는 기본값이고, 무관한 문서를 걸러줄 것으로 기대했다.

## 문제

문서에 분명히 답이 있는 질문이 근거를 받지 못했다.

- "주말 온콜 근무자 보상은?" → 문서에 "대체 휴가 1.5일" 이 있는데 일반 지식으로 답변
- "SEV-2 는 무슨 뜻인가?" → 문서에 정의가 있는데 엉뚱한 Red Hat 등급 체계로 답변
- "VIBE-2291 롤백 기준" → 이 질문만 정상 동작

## 측정

저장된 청크에 대한 각 질문의 최고 코사인 유사도를 직접 측정했다.

| 질문 | 문서에 존재? | 유사도 |
|---|---|---|
| VIBE-2291 롤백 기준 오류율 | ✅ | 0.5537 |
| API 키 보관 위치 | ✅ | 0.4036 |
| 프로덕션 배포 시점 | ✅ | 0.3987 |
| 주말 온콜 보상 | ✅ | 0.3011 |
| SEV-2 의 뜻 | ✅ | 0.2692 |
| 김치찌개 끓이는 방법 | ❌ | **0.3101** |
| 파이썬 웹 크롤러 | ❌ | 0.3054 |

무관한 질문(0.3101)이 문서에 있는 질문(0.3011, 0.2692)보다 **높다.**
**어떤 임계값도 관련/무관을 분리하지 못한다.**

### 청킹의 영향도 함께 측정

동일 질문("주말 온콜 근무자 보상은?")에 대해:

| 청킹 방식 | 유사도 |
|---|---|
| 문서 전체가 한 청크 | 0.32 |
| 조항 단위로 분리 | **0.70** |

즉 점수가 낮은 근본 원인은 임계값이 아니라 **청크에 여러 주제가 섞여 유사도가 희석된 것**이다.
조항 단위로 쪼갠 경우 무관한 질문은 0.22 로 남아 분리가 명확했다.

## 결정

두 가지를 함께 적용한다.

1. **`chunkSize` 600 → 300** — 청크를 주제 단위에 가깝게 유지한다.
   특정 픽스처에 과적합되지 않도록 업계 통용 범위(256~512) 안에서 선택했다.
2. **`similarityThreshold` 0.5 → 0.2** — 순수 노이즈 하한으로만 쓴다.
   관련성 판단은 `topK` 로 후보를 좁힌 뒤 `rag-augment.st` 규칙에 따라 LLM 이 한다.

> **1번은 [ADR-0004](0004-docling-parsing-chunking.md) 로 대체되었다.** 청킹이
> docling HybridChunker 로 넘어가 `chunkSize` 설정 자체가 없어졌다. 2번은 유효하나,
> 근거가 된 위 유사도 수치는 TokenTextSplitter 기준이며 **재측정하지 않았다.**

## 대안과 기각 이유

| 대안 | 기각 이유 |
|---|---|
| 임계값만 0.3 으로 조정 | 측정상 분리 불가. 무관 질문이 관련 질문보다 높음 |
| `chunkSize` 를 60 토큰까지 축소 | 테스트 픽스처 과적합. 실제 문서에서 문맥 손실 |
| 질의에 Qwen3-Embedding instruction 접두 추가 | 점수 개선 가능성은 있으나 별도 기계장치 필요. 학습 프로젝트 범위 초과 |

## 결과

- 문서 기반 질문 3건이 모두 정확한 값으로 응답 (SEV-2 정의, VaultBridge-7 / 45일, 화요일 14:30 / 승인자 2명)
- 무관한 질문은 발췌를 무시하고 한국어 일반 지식으로 응답
- 트레이드오프: 무관한 질문에도 발췌가 주입된다. `allowEmptyContext(true)` 와
  프롬프트 규칙이 있어 무해하며, 진짜 근거를 조용히 버리는 기존 동작보다 낫다.

## 교훈

로컬 임베딩 모델의 절대 유사도 점수는 기본값을 그대로 신뢰할 수 없다.
임계값을 정할 때는 관련 질문과 무관한 질문을 모두 측정해 **분리 가능한 구간이
존재하는지부터 확인**해야 한다. 임계값 실패는 오류 없이 조용히 근거를 버리기 때문에
가장 발견하기 어렵다.
